Task E3 Paginated catalog

Implement GET /catalog; fetch GET /pages?cursor=0 and follow opaque next_cursor until null, with at most three pages. Require typed item id/name records, preserve documented order and return the complete list, each item once. Never invent a cursor, declare a partial response complete or accept a continuation cycle. Give identical examples, cursor rules and deadline information to both groups. Use distinct IDs in the primary clean catalog. If an identical item ID/name appears again across pages, retain its first occurrence once in first-seen order. Conflicting records for the same ID or a continuation cycle return 502. Freeze these duplicate/overlap semantics in the common contract.

Each page has {"items": [{"id": integer, "name": string}, ...], "next_cursor": string or null}. The final response has {"items": [...]}. Continuation tokens are opaque; never invent a token.
