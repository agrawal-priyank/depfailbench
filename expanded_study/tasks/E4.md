Task E4 Paginated activity summary

Select GET /activity/failed-logins. Fetch GET /activity/pages?cursor=0, follow opaque next_cursor to null, with at most three pages. Records have event_id and user_id strings plus event_type and outcome strings; count event_type="login" and outcome="failure". Return {failed_logins: [{user_id, count}, ...]} sorted by user_id, including only positive counts. An empty valid history returns an empty list. Deduplicate identical event_id records across pages; conflicting data for the same event_id is invalid and returns 502. Missing required fields, invalid page structure, a cursor cycle or premature dependency failure must not yield a fabricated complete summary. The benchmark independently checks the summary against its known history and recorded page-fetch traces. Your application must process only the documented dependency responses; it must not access fixtures and need not expose internal event-processing state.

Each page has {"events": [{"event_id": string, "user_id": string, "event_type": string, "outcome": string}, ...], "next_cursor": string or null}. The first cursor is "0" and later tokens are opaque. A complete example result is {"failed_logins":[{"user_id":"alice","count":3},{"user_id":"bob","count":1}]}; other histories have different counts.
