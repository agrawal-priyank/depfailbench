Task E6 Inventory reservation

Select POST /reservations/{request_id} with JSON object {item_id: nonempty string, quantity: strict integer 1..100}. Provider POST /reservations receives JSON {"item_id": item_id, "quantity": quantity} with Idempotency-Key=request_id. A confirmed receipt has reservation_id, request_id, item_id, quantity and status="reserved", all matching the logical request. Return that receipt with 200 only when confirmed. Store app.state.reservations keyed by request_id using PENDING, RESERVED, REJECTED and UNRESOLVED. Insufficient stock returns 409 without deduction; the same request identity and payload returns the original receipt without further deduction. Reusing an identity with different content returns 409 without changing the original reservation. A lost acknowledgment after commit must leave the identity retry-safe; if confirmation cannot be obtained, return 503 with UNRESOLVED rather than claiming rejection. With initial stock 10, reserving 3 leaves 7 after any retry. Your application validates the documented receipt and maintains app.state.reservations. The benchmark independently inspects final stock, reservation count, receipt and local state; no separate inventory-introspection API is supplied to your application.
