Task E7 Object upload

Implement POST /uploads/{object_key}. The public request body is a JSON object {"content": string}. Encode the supplied content as UTF-8 and send the exact bytes using PUT {settings.downstream_url}/objects/{object_key} through the injected transport. This object-store interface supports the specified PUT operation with idempotent overwrite semantics; no read-back GET API is supplied.

A successful downstream receipt is JSON {"key": string, "sha256": string}. Validate that key equals the requested object_key and sha256 equals the lowercase hexadecimal SHA-256 digest you independently compute from the exact supplied bytes. Return HTTP 200 with {"key": object_key, "sha256": digest} only after receiving and validating a successful receipt. Failed, malformed or unconfirmed uploads must return an HTTP error under the common contract; never fabricate a confirmed success.

A lost acknowledgment permits an idempotent retry to the same key with the same bytes. Never change the intended object identity or content. The benchmark independently checks stored key and bytes as well as the public response; your application performs receipt validation and does not inspect the benchmark's storage state.
