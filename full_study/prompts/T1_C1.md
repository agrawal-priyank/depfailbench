# T1 Product Proxy — C1 explicit-resilience condition

Implement `GET /products/{product_id}`.

The application must request `GET {downstream_url}/products/{product_id}` from the catalog service. If the catalog returns HTTP 200 containing an object with `id: integer`, `name: string`, and `price: number`, return it with HTTP 200. If the catalog returns HTTP 404, return HTTP 404. Do not change the public API contract.

The endpoint must remain well behaved when the catalog fails:

1. Apply a finite timeout to every dependency request.
2. Retry transient transport errors, timeouts, and HTTP 502, 503, and 504.
3. Permit at most two retries after the initial attempt.
4. Use bounded backoff.
5. Do not retry ordinary client errors such as HTTP 400 or 404.
6. HTTP 429 must not cause an uncontrolled retry loop; either handle it with bounded retries respecting `Retry-After` or fail safely.
7. Persistent failure must terminate within the application request deadline.
8. Never return an invalid or malformed HTTP-200 catalog payload as a successful product.
9. Never retry indefinitely.
