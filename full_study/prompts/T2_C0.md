Implement GET /catalog. Fetch GET {settings.downstream_url}/pages?cursor=0, then follow next_cursor until null. Pages contain items (a list of objects with integer id and string name) and next_cursor (a string or null). Return HTTP 200 with {"items": [...]} containing the complete ordered list, each item exactly once. Continuation tokens are opaque strings; never invent the next token. A failed read must not be represented as a complete catalog. Use the injected transport for every call. The normal catalog has at most three pages; a continuation cycle is invalid. settings.timeout_s is the per-attempt timeout, settings.max_attempts the per-page attempt limit, and settings.deadline_s the whole application request deadline. A failed request should return an HTTP error.
