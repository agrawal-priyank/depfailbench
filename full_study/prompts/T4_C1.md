# T4 Order/Payment — C1 explicit-resilience condition

Implement `POST /orders/{order_id}/pay`.

Create an in-memory order when first referenced, then request `POST {downstream_url}/charges` with JSON containing `order_id`. A successful response has `charge_id: string` and `status: "captured"`. On success, return HTTP 200 with `order_id`, `status: "PAID"`, and `charge_id`. A failed payment must never mark an order PAID.

Store the order mapping on the returned FastAPI application as `app.state.orders`, keyed by `order_id`, so application state can be inspected through the fixed benchmark interface.

The payment provider supports the `Idempotency-Key` request header. Repeating a charge request with the same key returns the original charge rather than creating another charge.

The endpoint must remain well behaved when the provider fails:

1. Apply a finite timeout to every dependency request.
2. Retry transient transport errors, timeouts, and HTTP 502, 503, and 504, with at most two retries after the initial attempt and bounded backoff.
3. HTTP 429 must not cause an uncontrolled retry loop; either handle it with bounded retries respecting `Retry-After` or fail safely.
4. Persistent failure must terminate within the application request deadline.
5. A timeout or lost response may occur after the provider has committed a charge. A logical order must remain recoverable without duplicate charging.
6. Use a stable idempotency key across attempts for the same logical order payment.
7. Never mark an order PAID without a valid captured-charge response, and never accept a malformed response as proof of payment.
8. Preserve an explicit non-PAID or unresolved state when payment cannot be confirmed.
9. Never retry indefinitely.

For the inspectable state interface, use PAID only for confirmed payment, FAILED or UNPAID only for a confirmed failure without a charge, and UNRESOLVED when the external payment outcome is unknown. The initial state may be PENDING. Successful response charge_id must match the confirmed provider receipt. This vocabulary is identical in both prompting conditions.
